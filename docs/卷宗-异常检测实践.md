## 1. 核心框架：这是双向异常检测

本次案例最特别的发现：**我们在检测投放簇，平台在检测我们。同一套理论，两个方向。**

| 维度 | 平台检测爬虫 | 我们检测投放簇 |
|---|---|---|
| 建模的"正常" | 真人的浏览分布 | 真人的分享分布 |
| 主要特征 | 行为序列、速率、指纹一致性 | 内容模板、互动图、地理跨度 |
| **标签** | **有**（历史处置记录） | **没有** |
| 反馈 | 渐进且模糊 | 无 |
| 评价基线 | 未知 | 无 |
| 对抗 | 我们适应它 | 投放号适应我们 |

**最大的不对称是标签。** 平台能监督学习，我们只能无监督 + 人工。

这个对称性本身值得研究：**我们想施加给投放号的体验，正是平台施加给我们的。** 这既是最好的校准器，也是最好的伦理约束。

## 2. 理论 ↔ 实践：六组对照

### ① 正常性建模

**理论**：异常检测真正难的不是算法，是"正常"的边界。方法上对应密度估计、单类分类、基线构造。

**我们的实践**：
- 平台的"正常"是几亿真人的行为分布，它不需要定义"什么是爬虫"
- 我们的"正常"至今没定义清：判据 A 说"碗筷要对"，判据 D 说"同行占比要高"——但**多少算高？**

**当前难点**：
- 没有"正常笔记的评论区"基线，40% 同行占比无法解释
- 摆拍的"正常配比"也没有分布（真实就餐人均 1.5–2.5 道是常识，未验证）

---

### ② 上下文异常（Contextual Anomaly）

**理论**：同一个值，在不同上下文里含义相反。异常不取决于绝对值，取决于相对于什么。

**我们的实践**：
同样 40% 的同行占比：
- 基线 50% → 该号清白
- 基线 5% → 压倒性异常

**当前难点**：
- 基线段怎么切？（同城？同品类？同粉丝量级？）
- 平台的上下文可能更细（账号年龄、历史活跃度），我们完全没建模

---

### ③ 不平衡与评价

**理论**：异常率可能 0.1%，AUROC 会骗人，应看 AUPRC、Precision@K、告警预算下的最优阈值。

**我们的实践**：
- 我们只有"感觉像"，没有 Precision、召回、基线
- 案例 01 给出的 75 / 67.5 分是**拍的加权和**，不是概率，也没有验证过区分度

**当前难点**：
- 五条判据的权重（25/25/25/15/10）没有任何依据
- 不知道哪几条判据真的能分开"疑似"和"正常"

---

### ④ 结构异常（图与序列）

**理论**：图异常检测、子图发现、零模型与显著性检验。

**我们的实践（重要教训）**：
- 算出"58 对共现、34 人连通分量"，差点当成铁证
- 做零模型（保度序列边交换）→ p ≈ 0.17–0.35 → **与随机图无异**
- 图密度会随样本量自然增长，"看起来紧密"不等于异常

**当前难点**：
- 图指标的显著性检验必须成为流程，目前只有一次手工做过
- 时间维度的"突发检测"完全没做（同一批账号 30 天内推同一店）

---

### ⑤ 对抗与概念漂移

**理论**：检测对象会适应检测器；静态阈值必然失效；对抗性异常检测是一个独立研究方向。

**我们的实践**：
- 平台方向：14:40 给 461 → 我们无视 → 15:16 升级为限权（**它在观察我们的反应**）
- 我们方向：一开始抓"模板词"，投放号就换生造词（"吼吼吃"就是对抗产物）
- 平台从不告诉我们阈值——**给出明确阈值等于让对手拟合它**

**当前难点**：
- 任何一次成功的检测，都在教对手怎么躲
- 我们没有"模型衰减"的监测（告警率突然下降可能是对手适应了）

---

### ⑥ 可解释性

**理论**：不可解释的异常分无法用于决策；证据归因、人机协同。

**我们的实践**：
- 为什么用"五条判据 + 证据卡"而不是一个 0–1 分数？因为不可解释就无法使用
- 平台那句"行为异常"让我们排查了 40 分钟、判断错了两次——**这就是不可解释的代价**

**当前难点**：
- 我们的判据卡还是人工填写，没有结构化输出
- agent 给出的判断必须是可核验事实（"第 3 张图碗筷 2 副、菜品 9 道"），而不是结论（"这是摆拍"）

---

## 3. 已经确定的四条结论

1. **没有基线的异常检测不成立。** "40% 同行占比"在补上基线前等于零信息。
2. **图指标必须配零模型。** 这不是可选步骤，是定义的一部分。
3. **对抗环境下异常是动态的。** 平台在升级，投放号在升级，阈值会衰减。
4. **可解释性是可用性的前提。** 说不出理由的分数在真实决策里等于噪声。

## 4. 当前难点清单（按阻塞程度排序）

| # | 难点 | 阻塞什么 | 可能的出路 |
|---|---|---|---|
| D1 | **没有基线** | 所有比例类判据 | 采 5 篇同城普通笔记 + 二跳评论者 |
| D2 | **没有标签** | 无法算准不准 | 人工标注（工作台已就绪）→ 当黄金集 |
| D3 | **采集受限**（账号限权） | 拿不到新样本 | 等冷却 / 换数据源（OpenCLI、第三方） |
| D4 | 五条判据权重无依据 | 分数不可信 | 用标注数据算区分度 |
| D5 | 时间维度未建模 | 漏掉"突发"这类强信号 | 加时间聚拢判据 |
| D6 | 视觉判据不可批量 | A 判据只能人工 | 多模态 agent + 结构化输出 |
| D7 | 单案例、单城市 | 结论泛化性未知 | 换城市/品类复现 |

## 5. 观察框架：要持续记录什么

### 5.1 每次案例必记

```
案例编号 / 日期 / 城市 / 品类
样本量：笔记数 / 评论数 / 账号数
五条判据的状态与证据
簇的形状（恒星 / 网状 / 共享卫星）
结论 + 置信度 + 反证
事后验证：有没有被推翻
```

### 5.2 三个长期指标

| 指标 | 含义 | 当前值 |
|---|---|---|
| **同行占比** | 评论区被同行占据的程度 | 40%（无基线） |
| **图闭合度** | 外围之间的边 / 可能边 | ≈0（零模型阴性） |
| **预警提前量** | 从"失败率上升"到"被封"的时间 | 未测 |

第三条对未来最有价值：**如果能提前 30 分钟预警，配额管理就从"撞墙"变成"刹车"。**

### 5.3 平台侧观察（我们被检测）

| 观察项 | 记录 |
|---|---|
| 触发点 | 88 篇 / 800 评论 / 单日 |
| 升级路径 | 461 → 36 分钟后限权 |
| 恢复时间 | >24h（未恢复） |
| 判定粒度 | 非设备（换浏览器无效）、非会话（重登无效） |
| 反馈形式 | 网页正常，接口全拒 |

## 6. 待验证假设（核心）

每条都写成可证伪的命题。**证伪比证实更有价值。**

| ID | 假设 | 验证方法 | 所需数据 | 状态 |
|---|---|---|---|---|
| **H1** | 同城普通笔记的同行占比 < 15% | 采 5 篇 + 二跳 15 人 | 20 篇 | 待验证 |
| **H2** | 真实投放簇存在"三角闭合"（A评B、B评A） | 已有数据算双向边 | 已有 | 部分否定（样本内未见） |
| **H3** | 时间聚拢比图闭合更强 | 同一批账号 30 天内推同一店的比例 | 需时间序列 | 待验证 |
| **H4** | 摆拍的碗筷/菜品比可分布区分 | 人工标注 50 张图 | 图片 | 待验证 |
| **H5** | "同模板换地名"在投放号显著更常见 | 对比投放号 vs 普通号的标题模板率 | 200 篇 | 待验证 |
| **H6** | 限权恢复时间随撞墙次数递增（累加惩罚） | 记录每次 T 与 R | 需 3 次撞击 | 待验证（当前 1 个点） |
| **H7** | 网页正常 + 接口全拒 = 账号级限权，非 IP | 换出口 IP 复测 | 需另一出口 | 待验证 |

**H6 和 H7 是平台侧假设，H1–H5 是投放侧假设。** 两边都要观察，因为它们是同一套理论的两个方向。

## 7. 反脆弱：数据拿不到时做什么

采集受限是常态，不能让整个研究停摆。

| 有数据时 | 没数据时 |
|---|---|
| 采样本、算指标 | 整理已有 160 篇、重跑旧指标 |
| 验证新判据 | 完善判据表述、写教学贴 |
| 二跳展开 | 用合成数据验证算法（已做：3 跳） |
| 补基线 | 定义基线该怎么切 |

**已有数据还能榨出很多东西**：160 篇笔记、约 1500 条评论、270 张图，足够做 H2、H4、H5 的初步验证。
